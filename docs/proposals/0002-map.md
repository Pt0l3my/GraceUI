# Proposal 0002: The map

**Status: proposal, 2026-11-14 (EldenNet roadmap S7.9.a).** It changes nothing by itself: the decided design stands
until the owner answers G21 to G26 (§13), and each answer's effect is stated with its question. What it settles itself
is listed as proposed D-entries (D89 onwards, §12), each open to the owner. A mock-up on an invented island (its
places and people invented too, the game's map replaced by a painted stand-in) was made on a private design canvas for
the owner's review; it is not product code and is not in this repository. A bare § is a section of
[DESIGN.md](../DESIGN.md); "§4.5 of proposal 0001" points into [proposal 0001](0001-ui-framework.md).

## 1. What the owner asked

On 2026-11-14 the owner asked for an interactive map in the UI:

> I was also wondering if we could graphic interactive map to our UI which would track playthrough of the user, so it
> would show current quest progression, NPC placements and their recent trails, world state (as the map changes it
> updates topography), and of course the AI notes (memories that are relevant and could be added as lore). What is
> your opinion, what would you design for this? Keep in mind I would like this to be high quality map with tooltips and
> glowing effect, etc.

Told that the game's map image cannot be shipped, even altered, the owner asked for the player's own copy instead:

> can we not use the standard game map image as template in the UI? we can alter or add as we please, so it would be
> different.

> but perhaps the UI could render the map image from the game process and open the UI map instead of the standard in
> game map with the same hotkey (could be a toggle setting)?

> we could also make the game map image rendering into the UI map a toggle option (since some people might use custom
> map image that doesn't fit well.

And then: "yes, write the proposal and the mock-up".

## 2. The map in one page

A map of the player's own journey: where they have been, whom they met and where, how those people's stories went as
far as the player saw them, what changed in the world, and the notes the player keeps. It follows every spoiler rule
(SP1–SP9): only what the player has reached is drawn, and nothing else is shown, counted or hinted at.

```
EldenNet's core (reads the game; masks; projects)          GraceUI (draws; never touches the game)
  map image reader (S7.9.c) ── fit check ── mask ──►  tiles / one in-game texture (G21, G26)
  places reached, resting places, felled foes  ─┐
  sightings of profiled NPCs (trails, D89)      ├─►  the `map` projection ──►  the map panel (D91)
  quest steps seen (verified flags only, SP6)   │                              in the browser: WebGL, glow, tooltips,
  world stages that hold (O51) + our overlays   │                              zoom, the journey timeline
  memories with a place; lore notes (G23)      ─┘                              in game: vertex lists, one texture,
                                                                               a halo sprite; opened from the menu or
                                                                               by the map key (G25)
```

- **The framework part** (G16 (a), decided): a *map panel*, a new panel kind any mod could use once the framework
  opens (G18): a base (an image a mod hands over, or a vector drawing), layers of marks, lines, areas and labels, a
  tooltip and a detail pane from page data, zoom, and a timeline. GraceUI draws it; it never reads the game.
- **EldenNet's part:** the data (the `map` projection), the image, the masking, and its Map page (under G20 (a), in
  EldenNet's repository).

## 3. The base map (G21)

Three choices, one setting (Settings › Map, D95):

| Choice | What it is | When |
|---|---|---|
| **Your game's map** (default) | The map the player's own game shows, read from their game while it runs. GraceUI's layers are drawn over it | When the fit check passes |
| **GraceUI's drawn base** | A plain map drawn from the world's coordinates: coast, regions, contours, rivers, roads. Always lines up | The fallback, and the player's choice |
| **None** | No map: the layers on a plain background | The player's choice |

- **Why the game's own map, and only that way.** The map image is FromSoftware's artwork; an altered version is still
  a derivative of it, so no change makes it ours to ship, commit or show in our documents. Read at run time from the
  player's own game, it never leaves their PC: the same basis on which EldenNet reads game text (EldenNet `CLAUDE.md`,
  Licences). Our changes are applied live on their PC: our styling, our layers, our world-change overlays.
- **The fit check.** A map mod may replace the image with one of another size, framing or projection. EldenNet compares
  the image it reads with the vanilla map's size and aspect, recorded by the spike (S7.9.c); a mismatch draws
  GraceUI's drawn base instead, with a one-line notice that says why. A mismatched image is never drawn under the
  layers (D93).
- **Alignment, later.** For a custom map that almost fits: the player picks two places they have visited and points to
  each on the map; GraceUI scales and shifts its layers to match. A later version; the setting shows it dimmed with its
  tag (G7).
- **Masking happens in EldenNet** (SP1, D90): the browser receives only tiles that touch a reached area, their edges
  masked; in game, see G26.
- **Getting the image** is the hard part, and a spike settles it (S7.9.c) before anything is built:
  - *From the game's memory.* The game probably loads its map textures only when its own map opens (a guess, to be
    checked); if GraceUI's map replaces it (G25), they may never load.
  - *From the player's install.* The map sits in the game's packed, encrypted archives. The keys can be read from the
    player's own game at run time rather than shipped, and the decompression library is already in the game's folder.
  - Either way: nothing of the game is committed or shipped; every structure relied on is verified independently in
    game or by a self-test (EldenNet O48); no me3 and no fromsoftware-rs (O47, O48); the spike also checks that the
    route stays within EldenNet's read-only rule, and asks the owner if it does not.
  - If no route works, the drawn base is the map, and the rest of this proposal stands.
- **A cache** (D94): the decoded image may be kept in EldenNet's own user folder on the PC, keyed by the game's version
  and the source file's hash, so it is decoded once. It is never uploaded, logged or put in a report.

## 4. The layers

| Layer | What it shows | Source | The rules that bind it |
|---|---|---|---|
| Discovery (always on) | Areas reached; resting places used; foes felled | EldenNet's event engine (snapshots, flag watcher) | SP4 (seen before listed), SP5 (absence is silent), SP6 (strict) |
| People and trails | Each profiled NPC where the player last met them; their trail: the places the player met them, in order, older steps fainter | A sightings store (D89) | SP7 (perception); the veiled look for a perceived NPC the game has not named (SP5) |
| Quests | The steps of a story the player has seen, as a thread joining the places they were seen; the latest step glows | `stage_seen` (MEM §2.2), verified flag blocks only | SP6 (an unverified flag unlocks nothing); no counts, no "3 of 7", no next step (SP5) |
| World changes | A world stage that holds (O51), with the change it brings to the map drawn by us (a flood, a beacon gone dark, a city in ash) | World stages; a table of our overlays keyed by stage | SP6; only where the area is reached |
| Notes | Memories tied to a place, as pins; lore notes kept by the player or proposed from memories (G23) | EldenNet's memories (MEM) | SP2 (the lock filter); model text only on the pages that show it (PV) |
| You | In game, where the player is; in the browser, where they were last | The world snapshot | — |

- **The journey timeline** (D96) replays the playthrough from EldenNet's event log: dragged back, the map shows what
  was reached, who was met and what had changed at that play time. It never goes past now.
- **Tooltips and the detail pane** carry only projected text: names as the game shows them (SP3), when and where last
  met, the public line of the stage last seen, the note's text and the memories it cites. Search, titles and URLs carry
  no story text (SP9).
- **Trails are sightings, not tracking** (D89). Elden Ring's NPCs do not wander; they move between places as their
  stories advance, and EldenNet sees only the characters loaded near the player. A trail is therefore the places the
  player met someone, in order, never a position the player did not perceive.

## 5. Two views

- **In the browser** (G17 (a)): the full map. WebGL2 with a bloom pass for the glow, smooth zoom and pan, tooltips, the
  timeline, the detail pane; tiles from the loopback server (invariant 4), from our own code with no CDN or remote
  font (invariant 6). Reduced motion is respected.
- **In game**: the map panel drawn from vertex lists (invariant 10), the image uploaded once when the game starts, at
  a reduced size (invariant 11; at most 2048 × 2048 RGBA, 16 MB, unless measured otherwise), the glow as one soft
  halo sprite baked into the atlas at load, so nothing is uploaded later. Danger closes it at once (invariant 9), as
  every menu; the game does not pause.
- **Where it lives** (D92): EldenNet's Map page, its own category between Characters and History, under G20 (a);
  opened from the menu (F5), in the browser, or by the map key (G25).

## 6. The map key (G25)

- A setting, **The map key opens**: the game's map (default) or GraceUI's map. With GraceUI's map chosen, GraceUI
  catches the press, and the game never sees it, with the input machinery that keeps the menu's closing press from
  reaching the game (invariant 8; §4.5 of proposal 0001).
- **Fast travel and markers stay in the game's map.** v1 has no actions beyond dialogue, so GraceUI's map cannot fast
  travel or place markers. The game's map stays one press away: the map key pressed again inside GraceUI's map, or
  held, opens it; the game's own menu keeps its map entry. Fast travel from GraceUI's map is a later-version seam, like
  every action.
- **What the spike checks** (S7.9.c, with S4's input checks): catching the key on keyboard and pad, after the player
  has rebound it in the game; that holding and pressing again are distinct; and that nothing leaks to the game.

## 7. Glow and motion (G22)

The owner asked for a glowing, high-quality map. Invariant 14 forbids looping animation (cost and calm). This proposal
keeps it: the glow is still (marks, quest threads, the selection, a beacon), hovering brightens a mark, and a thing new
since the map was last opened flares once and settles (off under reduced motion). A setting chooses full, soft or no
glow (D95).

## 8. Lore notes (G23)

A note is a short line of lore in the player's map: "the ferry runs only at low water", pinned where it belongs. Who
writes it is G23. Under the recommended answer the model proposes a note from two or more of the player's memories
tied to the same place or person, citing them; it joins the player's notes only if they keep it (or edit and keep
it), and dropping it is final for that pair of memories. Proposals are few and batched, on a light model slot, under
EldenNet's pacing; each passes the lock filter (SP2); notes are stored per playthrough with the save's timeline (MEM)
and shown on Map and History › Memories.

## 9. Privacy, security and licences

- **The player's map** never leaves their PC except to their own browser on loopback, or a paired device on their home
  network when they have switched that on (G9, invariant 4); never in a log, report, URL or support bundle (PV1–PV8).
- **Tiles** are served only for reached areas and only to an authorised session; the server lists them in no index.
- **No FromSoftware material** in either repository: no map image, tile, screenshot of it or traced outline. Documents
  and fixtures use invented land, as the mock-up does.
- **No new dependency** is needed: WebGL is the browser's own; the in-game panel uses GraceUI's drawing. Any library
  considered later is licence-checked first and listed in `NOTICE`.

## 10. What EldenNet must change

Recorded in [eldennet-changes.md](../eldennet-changes.md) §10:

1. The map image reader, its fit check, cache and masking (S7.9.c first).
2. World positions to map positions: the open world's tile grid, the legacy dungeons' own frames (a conversion table
   is likely in the game's parameters; to be verified), and the underground and the expansion as separate sheets. A
   DataPiler job can read the numbers for research; EldenNet verifies them in game (O48).
3. The sightings store (D89): for each profiled NPC the places and times the Tarnished perceived them, with the stage
   then; it extends the "last met" record of the Playthrough page (§2 item 4 of eldennet-changes).
4. A table of map overlays keyed by world stage (O51), drawn by us.
5. The `map` projection and its topics (marks, lines, areas, tooltips, timeline events), public fields only (SP1).
6. Lore-note proposals (G23).
7. The map key (G25), with GraceUI's input.

## 11. Increments and risks

- **Order.** The design fold (S7.8.c) first; the spike (S7.9.c) as research, early, because the image route decides
  the most; the build when G24 says.
- **Risks.**
  - No route to the image works: the drawn base is the map (designed in).
  - The map key cannot be caught cleanly on every input path: the setting stays off where it cannot (G25 defaults to
    off).
  - Video memory: the in-game texture is capped (§5) and measured.
  - Spoilers through the image: masking in EldenNet (D90), and goldens that render the map at fixture states and check
    that no unreached pixel is drawn.

## 13. Questions for the owner (G21 onwards, in the order recommended)

### G21: What is the map drawn on?

- **As it would be put.** **(a) The player's own game map, read from their game at run time, masked and never
  shipped, with GraceUI's drawn base as the fallback when it cannot be read or does not fit** (recommended), and a
  setting to choose the drawn base or none instead. **(b) GraceUI's drawn base only.** **(c) An image the player
  exports from their own install with a tool on their PC**, loaded from a folder they choose.
- **In plain words.** Should the map show the game's own map from your game (falling back to our drawing when a map mod
  does not fit), only our drawing, or an image you export yourself?
- **Recommendation: (a).** It is what the owner asked for ("render the map image from the game process", with "a
  toggle option" for custom maps), it ships nothing of the game, and the fallback keeps the map working whatever the
  spike finds. *What (a) gives up:* it depends on a route the spike has yet to find; until then the drawn base is the
  map.
- **What each answer changes.** (a): §3 as written; S7.9.c's image route; D90, D93, D94. (b): no image reader, no
  cache, no fit check; G26 falls away. (c): a player-side export step and its instructions; the fit check stays.

### G25: What does the map key open?

- **As it would be put.** **(a) A setting, off by default: the map key opens the game's map, or GraceUI's map when the
  player switches it on**; with it on, the key pressed again or held opens the game's map (recommended). **(b) Always
  the game's map**; GraceUI's map only from the menu and the browser. **(c) GraceUI's map by default.**
- **In plain words.** Should the game's map key be able to open our map instead, as an option you switch on?
- **Recommendation: (a).** The owner's words ("could be a toggle setting"); fast travel and markers stay in the game's
  map in v1, so the default should keep them one press away as they are now. *What (a) gives up:* players who would
  prefer our map must find the setting.
- **What each answer changes.** (a): §6; S7.9.c's input checks. (b): no key capture for the map. (c): as (a), with the
  default flipped and a first-run notice.

### G26: In game, how is the game's map kept to what the player has reached?

- **As it would be put.** hudhook 0.9.3 leaks one buffer per texture upload, so the in-game map can be uploaded only
  once (invariant 11), while new areas are reached during play. **(a) Upload the whole image once at start, at a
  reduced size, and mask it at draw time by the reached areas' shapes** (recommended): invariant 1 gains one narrow,
  tested exception, this texture, which no view shows unmasked and no projection, log or report carries. **(b) Upload
  it once, masked as at start**; areas reached during the session show on the drawn base until the next start. **(c)
  The game's map in the browser only**; in game the drawn base.
- **In plain words.** In game, may GraceUI hold your whole map in video memory and hide what you have not reached when
  drawing it, or must it only ever hold the parts you have reached?
- **Recommendation: (a).** One upload per session, new areas show the moment they are reached, and the guarantee that
  matters (nothing unreached is drawn, counted or hinted at) holds and is tested by rendering goldens at fixture
  states. *What (a) gives up:* invariant 1's "never receives" for one texture; a debugger reading video memory could
  see the whole map.
- **What each answer changes.** (a): invariant 1 gains its exception and a pixel golden; D90. (b): a second style in
  game until restart. (c): the in-game map is the drawn base only.

### G22: May anything on the map loop or pulse?

- **As it would be put.** **(a) No: still glow, hover brightening and one-shot flares; invariant 14 unchanged**
  (recommended). **(b) A slow ambient shimmer in the browser only**, behind a setting. **(c) Loops in both views**,
  behind a setting.
- **In plain words.** Should the glow stay still, with things brightening once when they are new or hovered, or should
  some of it gently pulse?
- **Recommendation: (a).** A still glow reads as high quality without the cost and distraction of motion that never
  stops; the in-game frame budget (invariant 10) has no room for per-frame animation; one rule for both views keeps
  them alike (invariant 12). *What (a) gives up:* the living shimmer some map mods use.
- **What each answer changes.** (a): §7 as written. (b): invariant 14 gains a browser-only exception and a setting.
  (c): invariant 14 is replaced by a setting, with a per-frame cost budget in game.

### G23: Who writes the lore notes?

- **As it would be put.** **(a) The model proposes notes from the player's memories, each citing them, and a note
  joins the map only if the player keeps it** (recommended). **(b) The player writes every note**; no model call.
  **(c) The model writes notes on its own**, and the player may remove them.
- **In plain words.** Should the AI suggest lore notes from what you have learned, for you to keep or drop, or should
  notes be yours alone, or added automatically?
- **Recommendation: (a).** It is the owner's idea ("memories that are relevant and could be added as lore") while
  keeping the player in charge of their own map; notes stay grounded, because each cites memories the player actually
  has. *What (a) gives up:* a little effort: nothing appears until kept.
- **What each answer changes.** (a): §8; one batched proposal job. (b): no model call; an editor only. (c): the job
  writes directly; a "remove" action and a setting to turn it off.

### G24: When does the map ship?

- **As it would be put.** **(a) After EldenNet v1.0, as part of 1.1**, with the spike done early as research
  (recommended). **(b) In v1.0, the browser view on the drawn base only**; the game's map and the in-game view in
  1.1. **(c) All of it in v1.0.**
- **In plain words.** Should the map wait for the release after 1.0, arrive in 1.0 in a smaller form, or be part of
  1.0 in full?
- **Recommendation: (a).** EldenNet v1 is to be "deliberately minimal and stable"; the map depends on the spike's
  answer, on the framework's panel kinds (G16) and on the design fold (S7.8.c). The pieces v1 needs anyway (the
  sightings record behind Playthrough, the world stages of O51) land in v1 and make 1.1's map cheaper. *What (a) gives
  up:* players wait one release for the map.
- **What each answer changes.** (a): the build is planned for 1.1; S7.9.c early. (b): the panel kind and the browser
  view move into v1.0's scope; the image reader waits. (c): all of §10 moves into v1.0's scope.
